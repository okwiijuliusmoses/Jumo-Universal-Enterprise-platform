# JUMO UEOS — ERP DIGITAL HYBRID PLATFORM TRANSFORMATION DIRECTIVE

## Architectural Mandate
Every ERP must become an independent installable Digital Hybrid Enterprise Platform powered by JUMO UEOS.

### 1. ERP Public Landing + Authentication
*   Every ERP instance must use the approved JUMO DIGITAL ENTERPRISE PLATFORM public landing/login experience.
*   Flow: Public Landing Page → Authentication → Institution Identity → Portal Selection → Portal Authentication → Institutional Portal Workspace.
*   Never bypass portals.

### 2. Institutional Hierarchy (Mandatory)
Order: Platform → Institution Governance → Portals → Directorates/Offices → Departments → Modules → Components → Digital Forms → Workflows → AI Agents → Audit.

### 3. Portal First Architecture
*   A portal represents an institutional office (e.g., Academic Registrar, Bursar).
*   Portals must be expanded into true enterprise workspaces (100+ configurable operational modules).
*   Modules appear based on user role, department, permissions, and responsibilities.

### 4. UI & Navigation Standards
*   No sidebars. Use horizontal enterprise navigation + workspace transitions.
*   Standardize to: Microsoft Office style enterprise white background, neutral slate colors, professional enterprise typography, consistent spacing.
*   Implement complete navigation (Back, Forward, Breadcrumbs, Portal Switcher).

### 5. Platform Services
*   ERPs inherit core services: Identity Gateway, FAAP Financial Architecture, AEGIS Security, AI Platform, Workflow Engine, Forms Engine, Audit Engine, Notification Engine.
*   Centralized Owner Control Center for all configurations.

### 6. Implementation Principles
*   **No Dashboards:** Replace all static cards/dashboard widgets with functional workspace interfaces.
*   **Independent Platforms:** Every ERP must operate as a standalone installable instance while sharing core services.
*   **Configurable Registry:** Structures are generated from a central registry, not hardcoded.
*   **Operational Workspaces:** Every portal must provide enterprise-level operational modules (100+ roadmap).
*   **Uniform Branding:** Use JUMO branding exclusively; no demo, institutional, or university-specific placeholders.
*   **Role-Based Resolution:** Workspaces and modules are resolved based on authenticated user roles and permissions within their assigned portals.
*   **JUMO Front Desk Assistant:** Mandatory floating AI receptionist on all public landing pages.

## JUMO UEOS — Independent Commercial Platform Architecture Enforcement Instruction

### Purpose

JUMO UEOS is not a collection of dashboards, cards, landing pages, or ERP mockups.

All independent commercial platforms inside JUMO DIGITAL HYBRID PLATFORM must be implemented as complete enterprise-grade platforms with their own:

- Platform identity
- Business architecture
- Governance model
- Domain structure
- Modules
- Departments/directorates
- User roles
- Permissions
- Workflows
- Digital forms
- Registries
- Transaction engines
- Reporting systems
- Compliance controls
- Integration layers
- APIs
- AI capabilities
- Audit trails

Do not generate generic cards, placeholder dashboards, statistical tiles, marketing sections, or template pages as a substitute for real implementation.

A platform homepage is not an architecture.

Every platform must behave like an independent commercial software product.

### Strict Implementation Rules

#### Prohibited Generation Patterns

Do NOT create:

- Generic dashboard cards
- Fake metrics panels
- Repeated ERP templates
- Copy/paste module layouts
- Empty forms
- Placeholder buttons
- Generic "management" pages
- Dummy workflows
- Generic administration screens
- Single architecture reused across unrelated platforms

If a platform requires a dashboard, it must be created from actual operational functions, transactions, workflows, and user responsibilities.

Each commercial platform must have:

**1. Platform Core**

Every platform requires:

- Platform runtime
- Configuration engine
- Tenant model
- Identity integration
- Role and permission engine
- Workflow engine integration
- Notification system
- Document management
- Audit logging
- AI assistant integration
- API gateway integration

**2. Governance Architecture**

Each platform must define:

- Executive governance
- Departments
- Operational offices
- Administrator roles
- Professional roles
- External user roles

**3. Operational Architecture**

Each platform must include:

- Operational modules

- Digital forms

### Final Enforcement Rule

Before implementing any platform, first design:

1. Business model
