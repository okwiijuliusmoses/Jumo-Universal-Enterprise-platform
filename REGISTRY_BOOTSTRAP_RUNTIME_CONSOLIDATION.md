# JUMO UEOS Registry Bootstrap Runtime Consolidation

## Objective

RegistryBootstrap shall become the single runtime entry point responsible for
building and registering every Enterprise Platform instance.

The runtime startup sequence shall be:

EnterprisePlatformTemplateRegistry
        ↓
RegistryBootstrap
        ↓
ERPGenerationEngine
        ↓
ERPInstanceRegistry
        ↓
ERPDiscoveryService
        ↓
ERPWorkspaceResolver
        ↓
Runtime API

## Startup Contract

RegistryBootstrap shall:

1. Load every Enterprise Platform Template.
2. Generate a complete runtime for each template.
3. Register every runtime in ERPInstanceRegistry.
4. Validate registrations.
5. Publish all runtimes to discovery services.
6. Make every ERP immediately available to the workspace resolver.
7. Expose every runtime through:

   /api/ueos/erp/catalogue
   /api/ueos/erp/:id/runtime

## Runtime Rules

RegistryBootstrap shall never:

- depend on ERPBlueprintRegistry
- depend on ERPEcosystemTemplateRegistry
- depend on ERPTemplateCatalogue
- manually build portals
- manually build modules
- manually build workflows
- manually build navigation
- manually build departments

Everything must be generated by ERPGenerationEngine from
EnterprisePlatformTemplateRegistry.

## Runtime Validation

Startup succeeds only when:

- Enterprise templates loaded
- ERP runtimes generated
- ERP instances registered
- Discovery registry populated
- Workspace resolver populated
- Runtime catalogue available
- Runtime endpoint available

If any validation fails, RegistryBootstrap must fail startup with a descriptive
error instead of silently continuing.
